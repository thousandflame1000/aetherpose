# Aetherpose 網頁介面

左邊是 3D 人體與場景，右邊是控制面板。13 款姿勢小遊戲與 Aether Combat 對打共用同一個頁面和場景。介面為繁體中文，遊戲名稱保留英文。

## 資料流

```
IMU 追蹤器 ──BLE──> aetherpose.exe ──ws :9009──> 控制面板（追蹤器、校正、設定）
                         │
                         └──ws :9009──> frontend/mesh_bridge.py ──ws :9010──> 3D 人體、小遊戲、對打
                                         (TransPose 推論)
```

- 頁面只開一條 mesh_bridge 連線。姿態封包帶 `joints_version`，重送同一版本的心跳不會重新觸發動作，也不會延長姿態有效時間。
- 人體網格在頁面上計算（`skinning.js`）：連線時姿態服務送一次 SMPL 範本、關節與每個頂點的四個骨骼權重，之後每個姿態只送 24 個關節旋轉。所以網格和遊戲用的關節是同一個姿態、同樣的更新率，也共用骨盆原點：人體旋轉後網格與碰撞位置不會錯開。
- 追蹤器資料以收到時間判斷是否新鮮；斷線、過期或數值異常的追蹤器不送進推論。
- 即時／混合輸入若顯示未校正，先到「準備」完成「校正身體」再開始遊戲或對打。校正進行中不能開局；其他頁面啟動校正或校正失效時，進行中的回合也會中止，不更新完成成績。示範資料仍可練習，但不能作真人驗收。

## 啟動與關閉

在 `aetherpose` 執行（上層的 `start.ps1` 也會呼叫它）：

```powershell
.\run.ps1                  # 開啟 http://127.0.0.1:18080/
.\run.ps1 -Combat          # 同一個介面，直接開在「對打」分頁
.\run.ps1 -Port 18090      # 換網頁埠
.\run.ps1 -NoBrowser       # 不自動開瀏覽器
.\run.ps1 -Restart         # 先關掉執行中的服務再啟動（更新程式後使用）
.\stop.ps1                 # 關閉網頁伺服器、mesh_bridge、後端（同 webui\stop.ps1）
.\stop.ps1 -KeepBackend
```

啟動後端前，Rust 程式碼（`src`、`Cargo.toml`、`Cargo.lock`）比 `aetherpose.exe` 新時會先執行 `cargo build --release`；後端已在執行時只提醒改用 `-Restart`。腳本只啟動還沒在跑的服務，並用執行檔或腳本的完整路徑確認是本專案的程式：埠被其他程式占用時不啟動，關閉時也不碰無法確認的程式。

| 服務 | 埠 | log |
|---|---|---|
| Rust 後端 `aetherpose.exe` | 9009 | `logs/backend.err.log`、BLE 連線紀錄 `logs/status_ble.log` |
| `frontend/mesh_bridge.py` | 9010 | `logs/mesh_bridge.err.log` |
| 網頁伺服器 `webui/server.py`（本資料夾與本機工具 API） | 18080 | `logs/http_server.err.log` |

## 介面

| 分頁 | 功能 |
|---|---|
| 準備 | 開始使用的地方：「開始步驟」清單（連上追蹤器 → 指派 6 個部位 → 校正身體 → 開始遊戲，標出目前卡在哪一步與缺什麼）、追蹤器清單與骨頭指派、藍牙狀態（搜尋中、已連線、找不到介面卡等）、身體校正；「自動指派」「重設航向」等追蹤器動作 |
| 進階 › 監控 | 各追蹤器的更新率、遺失率、訊號、電量與韌體磁力計校正狀態（訊號 -80 dBm 以下、遺失超過 5% 標成橘色，電量 15% 以下標紅並提醒充電）；「三軸 ↗」開啟該追蹤器的三軸方向頁；磁力計校正 |
| 進階 › 骨架 | 後端 IK 骨架的設定：身體比例、IK 平滑、濾波參數、虛擬地板、漂移與軌跡積分、腿長校正。只影響 OSC 輸出、錄製與除錯圖層的骨架線，不影響畫面上的 3D 人體（TransPose 直接用追蹤器資料推論）。「還原預設值」把這些設定改回預設（腿長校正結果不變） |
| 進階 › 系統 | OSC 輸出（VRChat 的 OSC 追蹤器 1–8 與 head）、ZUPT、錄製（後端 IK 骨架存成 CSV，放在 `aetherpose/recordings/`；檔名已存在時自動加上 `_2`、`_3`，不會覆蓋舊的錄製；無法建立檔案或寫入失敗時顯示原因，停止後顯示上次存的檔名）、序列埠（狀態以文字說明） |
| 遊戲 | 遊戲庫、多遊戲訓練、回合紀錄、場景設定、場景物件 |
| 對打 | Aether Combat 對打操作 |

- **頭戴裝置**：Quest 的頭與手姿態送到 UDP 9002 時，後端用它當頭與手的位置：整個骨架跟著頭戴裝置移動（蹲下、走動），頭固定在頭戴裝置的位置；超過 0.5 秒沒有新資料就不再使用，骨架回到原位。「進階 › 骨架」分頁顯示是否連線。漂移補償與腿長校正都需要它（漂移補償讓骨盆與腰的航向慢慢對齊頭戴裝置，設為 1 時約 10 秒）；腿長校正另外需要左大腿、左小腿追蹤器，條件不足時按鈕停用並說明缺什麼，失敗時說明原因（例如蹲得不夠深）。校正結果不對時按「重設比例」回到預設的 0.900。
- **設定**：「進階」裡「骨架」與「系統」分頁的控制項顯示後端存在 `config.json` 的值，改動會存回去；尚未按「套用」的輸入不會被畫面更新蓋掉。新連上的追蹤器自動分到空著的骨頭，已手動指派或存過的不會被重排；按「自動指派」才會依 ID 重新全部指派。選單選「未指派」會拿掉追蹤器的骨頭，之後連上的新追蹤器與重新啟動都不會再自動分配給它，直到再次指派（或按「自動指派」）。3D 人體只用頭、胸口、左右前臂、左右小腿 6 個部位，指派到其他部位的追蹤器只影響 IK 骨架（選單分成兩組，清單上也會標示）。分不出哪顆追蹤器是哪個 ID 時，用「搖動指派」：選部位、按下後用力搖一下戴在那裡的追蹤器。一個部位只會有一顆追蹤器：把追蹤器指派到別人已占用的部位時，兩顆互換部位（原本那顆沒有部位時改為未指派），面板頂端會說明。
- **資料來源**：左上角標示「即時動作捕捉」（6 個槽位都是即時 IMU）、「混合輸入（即時 n/6）」、「示範資料」或「推論錯誤」；即時追蹤器尚未校正時會加上「未校正」。滑鼠移到標示上可看到完整狀態與錯誤原因。
- **導覽**：面板上方是常用的「準備」「遊戲」「對打」；監控、骨架（IK）與系統設定收在「進階」裡，按下才展開第二列分頁，再按一次回到「準備」。分頁可用 Tab 移到後按 Enter，或用左右方向鍵切換；用鍵盤移動時，目前的按鈕、分頁或滑桿會有藍色外框。每個分頁最上方的主要卡片有藍色外框；較少用的工具（追蹤器工具、多遊戲訓練、回合紀錄、場景設定、場景物件）預設收合。
- **場景視角**：場景左下角的視角工具列有「正面／側面／俯視」選單、「重設」、「全部入鏡」（框入人體、對手與場景物件，不含訓練場的裝飾）與「跟隨」（鏡頭跟著人物移動）；拖曳後標示「自訂」，手動調整視角會關閉跟隨。
- **重新整理**：重新整理頁面會回到原本的分頁（記在這個瀏覽器分頁裡），網址保持不變。
- **版面**：場景右下角是「音效」「隱藏面板」「全螢幕」。「隱藏面板」讓場景佔滿頁面（這時面板的提示改顯示在場景上方，並多出「遊戲庫」「對打」可切換活動），「顯示面板」或 Esc 恢復；「全螢幕」使用瀏覽器全螢幕。遊戲進行中的提示顯示在場景下方正中央。切換分頁時面板捲回頂端。系統開啟「減少動態效果」時，「開始！」等提示只淡入淡出，分數與連線燈號不再跳動。
- **狀態提示**：後端沒連上時，追蹤器清單會說明；這時按下的動作會在面板頂端顯示「未送出」。姿態模型出錯時，面板頂端顯示原因與 log 檔位置，「開始步驟」也會一直寫著，直到問題排除；姿態服務斷線時左上角會說明怎麼恢復。面板頂端的提示可以按 × 關閉。停用的按鈕會變淡，滑鼠移上去或下方會說明原因。看不出效果的動作（重設航向、重設配戴、清除 IK 校正、套用 ZUPT）會在面板頂端確認做了什麼。顯示卡重設使 3D 畫面中斷時，進行中的回合結束為未完成，面板頂端說明正在恢復；8 秒內沒恢復就請你重新整理頁面。瀏覽器沒用顯示卡畫 3D（硬體加速關閉）時，啟動後會提醒開啟。
- **輸入檢查**：OSC 的 IP 要是 IPv4 位址、埠 1–65535；ZUPT 視窗 1–200、門檻大於 0；錄製的批次與寫入間隔要是範圍內的整數，檔名不能有 Windows 不允許的字元；不合格時不送出，並說明原因。
- **效能**：推論裝置（有 CUDA 時自動使用）、每秒姿態數與每個姿態的推論時間只在「除錯圖層」顯示；每秒少於 15 個姿態時左上角以橘字提醒（遊戲判定可能不準）。場景碰撞的 CPU 時間在勾選「顯示碰撞範圍」時顯示。

## 姿勢小遊戲

在「遊戲」分頁的遊戲庫選擇玩法，按遊戲庫裡或場景上方的「開始」（場景上方的按鈕在「對打」以外的任何分頁都能用）。遊戲庫的每張卡片有該遊戲動作的示意圖，可用中英文搜尋、收藏，選中後顯示操作說明與回合時間；玩過的遊戲在卡片上顯示目前資料來源下的最佳成績。

所有姿勢遊戲共用以下規則：

- 回合進行時，場景上方是計分板（分數、時間、最佳），保持動作時指示下方有進度條；計時開始時顯示「開始！」，結束時顯示「時間到！」並跳出結果卡（分數、是否新紀錄、資料來源、結束原因與最佳成績，可直接再玩一次或選其他遊戲；Enter 再玩一次、Esc 關閉）。場景夠寬時結果卡靠左，不擋住人物與機器人（對打時仍置中，避開兩側的 HUD）。對打結束時也有同樣的結果卡。場邊的記分板會同步顯示目前的遊戲與分數；姿勢遊戲時，機器人會在開始時揮手、得分時比讚、完成回合時跳舞。
- 開局前要站直、雙腳踩平並穩定 1 秒；畫面顯示校準進度與沒通過的原因（直立、頭與骨盆對齊、雙腳同高、高度穩定、更新間隔）。
- 每回合 60 秒。可「暫停」／「繼續」（暫停不計時、不計分，繼續後要重新保持動作）、按「結束回合」中途結束、關閉場景右下角的「音效」（記在這個瀏覽器）。
- 資料來源改變時（例如一顆追蹤器短暫斷線），回合先暫停最多 1.5 秒等待恢復，恢復就繼續、不扣回合時間，否則結束；追蹤中斷、資料過期或切到背景時回合自動結束；樣本間隔過長會重置保持時間。
- 最佳成績依玩法與資料來源（示範／混合／即時）分開記錄，只有完整跑完的回合才算。對打也一樣：擊倒對手、被擊倒、判定或時間到的回合會記錄最佳得分，中途停止的不算。
- 回合紀錄保留最近 50 場、顯示 10 場，可依遊戲與來源篩選、匯出 JSON；「清除紀錄」不影響最佳成績，最佳成績用「清除最佳成績」另外清除；兩個按鈕都會先確認。「選回這款遊戲」可回到該玩法。

| 遊戲 | 動作 | 判定重點 |
|---|---|---|
| Reach Targets | 伸手碰黃色目標，快速連續命中累積連擊 | 目標避開場景模型與對手；手到目標的路徑被模型擋住不算 |
| Squat Rhythm | 下蹲保持 0.5 秒，站直後才能再計分 | 頭降至少 18 cm、骨盆降至少 12 cm、雙腳踩平；只低頭不算 |
| Balance Hold | 依提示輪流抬左／右腳，保持 1.5 秒 | 兩腳高度差至少 12 cm、軀幹直立 |
| Dodge Flow | 依提示向左／右傾身，保持 0.4 秒，回中後換方向 | 頭橫移至少 16 cm、胸至少 8 cm、雙腳踩平 |
| Sky Catch | 雙手舉過頭碰高空目標，保持 0.35 秒 | 雙手放到肩膀以下才能再得分；單手或一直舉著不重複計分 |
| Clap Pulse | 胸前張開雙臂再合掌，保持 0.2 秒 | 張開時雙手距離超過 55 cm；每次得分要重新張開 |
| March Step | 交替抬膝抬腳，保持 0.3 秒，兩腳落地後換邊 | 抬膝以骨盆為基準，放下另一腳不能作弊 |
| Star Hold | 雙臂伸直在肩膀高度，保持 0.8 秒 | 以肩–肘–手判斷伸直；彎肘或單手不算 |
| Cross Knee | 用對側手碰抬起的膝蓋，保持 0.3 秒 | 膝蓋要相對髖部抬起、腳要離地 |
| Guard Drill | 雙手放在頭部兩側，保持 0.8 秒 | 手的距離依校準身高調整；雙手降到胸口以下才能再開始 |
| Shoulder Tap | 雙手交叉碰對側肩膀，保持 0.6 秒 | 兩手都離開肩膀至少 28 cm 才能再得分；單手、同側、軀幹歪斜不算 |
| High Five | 依提示用單手碰高處目標，保持 0.3 秒，另一手在肩膀以下 | 目標被場景模型擋住時停止累積 |
| Bow Rhythm | 向前彎身保持 0.6 秒，站直後再做下一次 | 雙腳保持同高 |

**多遊戲訓練**：上肢（Clap Pulse → Shoulder Tap → High Five）、下肢（Squat Rhythm → March Step → Balance Hold）、混合（Reach Targets → Dodge Flow → Cross Knee），或從全部 13 款自訂三關。每關是完整 60 秒回合，完成後按「開始下一關」；未完成可重試。全部完成後可匯出訓練報告（JSON），最近一次完成的報告會保存在瀏覽器裡。

## Aether Combat 對打

在「對打」分頁按「開始回合」開始 90 秒回合。對手是 Quaternius 的 CC0 RobotExpressive 模型（`assets/robot`），會依戰況播放攻擊、受擊、倒地與勝負動畫；模型載入失敗時改用備用對手。

- **攻擊**：出拳（手快速揮出、高度至少到胸口）或踢腿（腳快速離地），打中亮起的部位（頭、身體或腿）。
- **防禦**：高位攻擊用雙手護頭或蹲下；身體攻擊用護頭；側面攻擊把身體往旁邊傾。
- 「對手距離」調整 0.8–1.8 m（預設 1.1 m），調整會重設回合；「回到中央」把你的位置重設到擂台中央。
- 有完整的新鮮姿態才能開局；斷線或姿態超過 5 秒沒更新時停止回合並隱藏人體。離開「對打」分頁會結束回合。
- 間隔過久的樣本與瞬間位移不會被當成快速攻擊。
- 設為實心的場景模型會擋住雙方的攻擊：你的手與腳以球體（半徑 0.11 m／0.12 m）沿路徑檢查模型三角面，被擋住時不造成傷害並中斷連擊；對手的攻擊被擋住時也不會傷到你。
- 骨架、碰撞框與地板格線可在「遊戲 › 場景設定」的「除錯圖層」開啟。

## 場景物件

在「場景物件」匯入自帶貼圖的 GLB 2.0 模型（單檔最多 20 MB），或從場景庫加入木燈籠、機器人（CC0，來源見 `assets/README.md`）。場景最多 8 個物件，匯入時縮放到最長邊 1.2 m 並放在地板上。

- **編輯**：側欄可調位置、離地高度（0–2.5 m）、大小（0.25–2 倍）與水平角度。勾選「在場景中編輯模型」後可直接在場景拖曳：W／E／R 切換移動／水平旋轉／等比例縮放，「吸附」對齊 0.1 m、15°、0.05 倍。
- **管理**：複製、重新命名、「顯示」、「實心碰撞」（關閉時只當裝飾）、「檢視選取的物件」。每個物件可復原／重做 50 步（Ctrl+Z／Ctrl+Shift+Z）。
- **保存**：「儲存場景」存在這個瀏覽器（IndexedDB），重新整理後用「還原儲存的場景」還原；「匯出場景檔」／「匯入場景檔」用 `.aetherscene` 檔備份或搬到別台電腦。毀損或不支援的檔案不會覆蓋目前場景。
- 改變實體物件（新增、移除、移動、顯示或碰撞設定）會把進行中的回合結束為未完成，避免編輯造成的位移被算成得分。

## 身體校正

TransPose 需要知道每顆追蹤器怎麼戴在身上、使用者面向哪裡。每次穿戴後在「準備」分頁按「校正身體」，照提示做：

1. T-pose：站直、雙臂向兩側平舉，靜止 2 秒。
2. 保持手臂，從髖部向前鞠躬約 45°，靜止 1.5 秒。

T-pose 算出每顆追蹤器的配戴偏差，鞠躬時胸口（沒有時用頭部）追蹤器傾斜的方向就是使用者的正前方，因此不需要知道感測器的軸向。同一個 T-pose 也會重設後端 IK 骨架的配戴。按鈕需要一顆已連線、指派到胸口或頭部的追蹤器；動作晃動、鞠躬太淺時會說明原因，原本的校正保留不變；「取消」也一樣保留原本的校正。

未校正的即時追蹤器仍會送進推論，但姿態不正確：資料來源標示會加上「未校正」，校正卡片也會提醒。示範資料本身已在 SMPL 座標系，不受影響。新連上的追蹤器要重新校正。

## 磁力計校正

「進階 › 監控」分頁的「磁力計校正」直接執行 `tools/calibrate_tracker.py`，不必開終端機：

1. 後端連上該追蹤器後，在「追蹤器」選它，按「開始校正」，慢慢把追蹤器轉過各個方向；三軸涵蓋率夠了會自動停止。錄製需要追蹤器正在傳送資料。
2. 擬合結果寫進韌體的校正表；勾選「錄完後燒錄韌體」時接著編譯並燒錄到以 USB 連接的追蹤器，最後讀開機訊息確認磁力計已啟用。
3. 「只燒錄」只燒錄目前的韌體（例如把校正表帶到另一顆追蹤器），「取消」中止，連同工具啟動的 arduino-cli 編譯或燒錄一起停止。燒錄中途取消時，板子可能停在 bootloader（燈慢慢閃）：按兩下 reset 鍵後再按「只燒錄」。

工具輸出即時顯示在卡片下方；重新整理頁面後會接著顯示進行中的執行。每顆追蹤器的指標列顯示「磁力計已校正」（韌體表裡有它的校正值，燒錄後生效）或「磁力計未校正」（航向只靠陀螺儀，會漂移）。

頁面伺服器只接受本機（127.0.0.1／localhost）、同源且帶 `X-Aetherpose` 標頭的工具請求，其他網站無法替你觸發燒錄；同時只執行一個工具。後端（9009）與姿態服務（9010）的 WebSocket 也只接受本機頁面，其他網站開的連線會被拒絕（403）。

## 碰撞

- 場景有後牆與兩根柱子。人體網格每幀計算包圍盒，與地板、場景物件和對手軀幹以連續掃掠檢查，快速移動也不會穿牆；碰到時沿表面滑動，不改變收到的動作資料。
- 每個可見網格各自有包圍盒，物件之間的空隙可以通過。目標放置、手到目標的路徑與對打的攻擊路徑則檢查實際的三角面（以 CPU 上的空間樹加速）。
- 限制：人體與場景之間是保守的包圍盒碰撞，不做逐三角面碰撞、關節角度限制或自身碰撞，也不使用 GPU 物理。
- 「顯示碰撞範圍」顯示人體範圍（綠，接觸時紅）、場景物件（藍）與對手軀幹（黃）。追蹤中斷、切換來源與「回到中央」會清除碰撞歷史。

## 畫面設定

「場景設定」提供低／平衡／高三種畫質（低：關閉陰影並限制解析度；高：2048 陰影貼圖）與亮度調整，「重設外觀」回到平衡／1.10。首次使用且偵測到軟體 WebGL 時預設採低畫質；已儲存的畫質偏好優先。「儲存視角」／「還原視角」保存相機視角；「儲存場景 PNG」下載目前畫面。設定存在這個瀏覽器，不改計分規則。

## 注意事項

- 需先完成 `..\setup.ps1`：後端已編譯、有 Python 環境、外部檔案（TransPose、SMPL）路徑正確。
- Three.js 0.128.0、OrbitControls、GLTFLoader、TransformControls 放在 `vendor/three`（MIT），頁面不依賴 CDN。
- 只用靜態伺服器開頁面時，「進階 › 監控」分頁的校正工具會停用（`run.ps1` 會把舊的 `python -m http.server` 換成 `server.py`）。
- 一顆追蹤器同時只能被一個程式透過 BLE 連線。「進階 › 監控」分頁的「三軸 ↗」開啟 `imu_axes.html`，直接讀後端資料檢查單顆 IMU 方向；用 `tools/imu_axes.py` 直連 BLE 時要先關掉後端。
- 追蹤器韌體更新後（例如座標系或濾波器改變），在「準備」分頁重新做「校正身體」。
- 回合結束原因在程式與回合紀錄裡以英文代碼保存（例如 `Time's up` 代表完整回合），畫面顯示時翻成中文；舊紀錄照樣能讀。

Combat 敵人使用自適應加權選招：持續防守會增加側擊機率、蹲下會增加身體攻擊、側身閃避會降低側擊機率。每回合記住被防住的招式並減少重複使用，新回合重置記憶。攻擊分為蓄力、出招及恢復；蓄力階段的命中可打斷敵人，已出手的攻擊可互相換傷。Punch 動畫在出招階段啟動，敵人血量較低時略縮短蓄力，仍保留至少 0.9 秒預警。

Combat 難度提供練習、標準、挑戰三種選擇，分別使用 1.45／1.05／0.85 秒基本預警及較慢／標準／較快的恢復節奏。練習降低策略適應強度，挑戰提高策略適應強度；低血量預警仍不少於 0.75 秒。選擇保存在瀏覽器，下一回合才套用，避免進行中突然改變攻擊節奏。

Combat 敵人選招前會檢查各攻擊路徑的網格遮擋，被擋住的招式不參與選招；所有路徑受阻時會等待空檔，每 0.65 秒重新判斷。攻擊命中前再次確認遮擋，避免蓄力期間新增障礙後仍穿模傷害玩家。判定使用 6 cm 球形路徑。

防禦成功會使敵人播放失衡反應，增加 0.8 秒恢復時間，並提供 0.8 秒反擊空檔；期間命中提示目標的傷害提高 25%，畫面會顯示反擊提示。非目標命中不享有加成；追蹤暫時中斷恢復時，空檔會與回合時計一起補回凍結時間，新回合清除空檔。

Combat 回合結束會顯示命中數／有效出手数、命中率、正確目標命中、防守、反擊、受擊、最高連擊及被場景阻擋的出手次数。無效姿態或速度異常不計入出手，場景阻擋不會偽算成成功防守；開始新回合或重設會隱藏舊摘要。

對戰回合紀錄會保存当時難度與有效出手、命中、正確目標、防守、反擊、受擊、最高連擊及場景阻擋統計；回合歷史中顯示摘要，JSON 匯出也包含这些資料。舊紀錄仍可讀取；額外統計若格式不合法只移除額外資訊，不丟棄原本的分數紀錄。

對戰摘要與歷史會依實際統計提供下一場練習建議，區分場景遮擋、缺少防守、有效距離、打錯目標及未利用反擊空檔；只有命中率與防守表現穩定時才建議提高難度。

敵人來襲面板新增命中倒數與蓄力進度條，按招式顯示雙手防守、蹲下或側身閃避提示。追蹤暫時中斷時倒數與回合一起凍結；攻擊結束或被打斷後移除進度條。

追蹤來源短暫中斷的寬限期間，敵人動畫也會與攻擊倒數一起暫停；恢復時不補播凍結期間的動畫時間，避免 Punch 提前播完但傷害延後。反擊空檔提示同樣使用凍結時計。

Combat 目標面板顯示 4.2 秒命中時限與剩餘進度條，追蹤短暫中斷時同步凍結。每次換目標時光球及圓環會短暫放大，所有目標部位統一使用金黃色，與反擊及操作提示一致；結束回合時清除目標時計。

敵人的攻擊需在 1.7 m 判定範圍內：選招及命中前都檢查對應頭／胸目標的世界座標距離。玩家被碰撞推遠時，敵人等待進入範圍；蓄力後離開範圍則揮空，不扣血，也不算成功防守。

敵人動畫銜接會保留正在播放的同一個 Idle／No／慶祝片段，不因連續命中或重複教練事件把動畫反覆重置到第一幀；每次新的 Punch 出招仍重新啟動攻擊片段，已播完的片段也可以再次播放。

來襲面板在沒有待命中攻擊時，會區分對手恢復、失衡、場景遮擋與距離等待，恢復及失衡附剩餘秒數。追蹤中斷明確顯示暫停；結束及重設清除敵人狀態，避免上一回合狀態殘留。

機器人可見模型會以平滑的水平轉向面朝玩家骨盆位置，讓出拳與受擊動畫朝向對手；只改模型朝向，沿用原本碰撞代理、人體位置及共用場景。追蹤中斷期間凍結轉向，倒地動畫保持朝向直到新回合。

回合歷史新增對戰難度篩選，可與遊戲及資料來源一起使用；舊紀錄可選「舊紀錄／未指定」。選擇 Pose 玩法時自動清除並隱藏對戰難度，避免無關條件隱藏體感遊戲紀錄。

回合歷史提供目前篩選下的完成對戰總覽：按有效出手加權計算命中率，合計防守、反擊與受擊次数，保留最高連擊。只統計已有有效額外資料的完成回合，排除中斷及缺少統計的舊紀錄；來源與難度篩選會同步更新總覽。

敵人同回合內會記住成功命中的招式，依難度適度提高其選招權重；被玩家防住會減弱這項偏好。成功次數上限為 6，並保留重複招式降權與隨機選招，避免固定連發。新回合清除弱點記憶，场景遮擋及距离揮空不会增加偏好。

挑戰難度新增最多兩擊的敵人連招：第一招成功命中後有 50% 機率，經 0.65 秒準備接續第二招；有其他可用路徑時換招，第二招仍保留正常預警與遮擋／距離檢查。畫面標示連招準備及第二擊，玩家在準備期間命中可取消連招。練習與標準難度不使用此連招。

對戰摘要與保存報告會細分高位、身體及側面攻擊的受擊／防守次数。練習建議優先指出最常漏防的招式，並區分舉手、蹲下及側身的正確應對；載入時核對分類合計與總次数，不一致的額外分類資料會忽略，舊紀錄仍使用一般建議。

目標命中時限依對戰難度調整：練習 6 秒、標準 4.2 秒、挑戰 3.2 秒；進度條同步更新上限。難度變更仍只在下一回合套用，進行中不會突然縮短目前目標時間。

對戰歷史的弱點建議可直接選回對應 Pose 練習：側擊漏防對應 Dodge Flow，舉手防守不足對應 Guard Drill，瞄準或反擊銜接不足對應 Reach Targets。只切換玩法，不自動啟動回合；場景遮擋問題不推薦無關動作練習，原本紀錄保留。

Combat 結果視窗直接呈現命中、防守、反擊及連擊摘要與教練建議；有合適的動作練習時顯示「選擇建議練習」，切換同場景玩法並關閉結果，不自動開始。按鈕支援換行，結果內容過長可在卡片內捲動。

Combat 結果視窗新增「匯出本回合」，下載包含該場分數、來源、難度、完成狀態及詳細防守統計的 JSON，沿用版本 1 的 rounds 陣列格式。匯出後保持結果視窗，回合歷史的全部匯出仍可使用。

對戰結果統一由結果視窗呈現，移除場景下方重複的統計浮層，分類防守細節、練習建議及匯出功能均保留。重設與新回合會關閉結果視窗。

歷史每列新增「匯出本回合」，可下載過去的單場 Pose 或 Combat 紀錄，保留原完成時間、來源與對戰分類統計；操作按鈕以可換行的一列排列。匯出不清除紀錄、不切換場景，也不啟動新回合。

Combat 光球與圓環會向玩家所在的一側偏移 0.2 m，讓機器人轉向後的目標較容易看見；原命中區域與傷害判定保留。位置跟隨玩家世界座標，追蹤暫停期間保持，沿用同一個場景與渲染迴圈。

Combat 最佳分數新增難度與來源分組，完成的練習／標準／挑戰回合各自更新最佳；未完成回合不更新。結果視窗標示所屬難度，遊戲卡片依所選難度顯示最佳；舊版及全部難度的整體最佳仍保留，清除最佳成績也會清除各難度紀錄。

出手判定現在區分揮空與命中區域被場景遮擋：手腳已碰到對手代理區域但命中路徑受阻時，顯示遮擋提示並計入場景阻擋统计，不誤算成一般揮空，也不会讓對手播放受擊反應。仍可命中其他未被擋住的有效部位。

出拳判定改用手相對胸口的速度及向外伸出方向，排除回手、胸口與手同步移動造成的假出拳。手與胸口需有有效連續樣本，且手本身具有足夠速度；異常手部樣本不會借用胸口速度產生傷害。此計算不依固定世界軸。

踢擊需要有效連續腳部樣本、足夠速度、抬腳高度，且水平速度朝向對手；純抬脚踏步及收腳不計入踢擊出手。方向使用對手與玩家的世界座標，並套用人體根節點旋轉，真正向前抬脚踢击仍使用原腿部碰撞判定。

Combat 蹲下判定改用軀幹與腿部骨段估算站立高度，再比較目前頭部到腳底的比例，避免固定 1.2 m 閾值把較矮的站立角色當成蹲下。估算有上下界，保留來源及有效姿態驗證。

雙手防守需有適當分隔、分別位於頭部左右兩側，覆蓋方向沿肩膀軸判斷，因此轉身後仍可防守。兩手擠在同側或過度重疊不算完整防守；距離與分隔閾值依人體高度比例計算。

對戰未進行、切至背景或追蹤寬限暫停時，只更新姿態標籤，不消耗攻擊冷卻。追蹤恢復會將已接受的出手冷卻與回合時計一起延長凍結時間，避免幽靈動作阻塞第一擊，也防止利用追蹤切換跳過冷卻。

Combat 目標選擇會排除被場景遮擋的命中路徑，並每 0.25 秒重新確認目前目標。全部部位受阻時隱藏光球、圓環與目標時計，提示整理場景；恢復可用路徑後重新選目標並給予完整命中時限。回合時計仍照常進行。

當部分對戰目標路徑受阻，目標面板會列出仍可攻擊的部位；全部受阻時明確提示，全部可用時隱藏這行資訊。路徑列表每 0.25 秒更新，沿用目前的場景網格查詢。
