# 實體驗收與證據記錄

驗收項目與目標以 [畢設執行計畫](graduation-plan.md) 為準。每次試驗先複製 [實驗表](experiment-template.md)，填好測法與門檻，再開始記錄。

互動判定的人工標註、CSV 格式與混淆矩陣分析見 [深蹲試次分析](action-evaluation.md)。追蹤器穩定性與遊戲正確性分別取證。

## 記錄六顆追蹤器的穩定性

1. 用 `run.ps1` 啟動專案。實體驗收前停止模擬器，核對六顆裝置的 ID 與穿戴部位，完成指派及身體校正。
2. 在專案根目錄執行以下命令。ID 是範例，必須換成實際值，順序固定為頭、胸、左前臂、右前臂、左小腿、右小腿。

```powershell
..\.venv\Scripts\python.exe tools\record_experiment.py --seconds 600 --ids 10 20 30 40 50 60 --input-kind physical-ble --note "P01; firmware version: fill in; body calibration: done"
```

本專案若使用根目錄內的 `.venv`，將 Python 路徑換為 `.\.venv\Scripts\python.exe`。其他輸入可填 `physical-udp`、`simulated-udp` 或 `mixed`。輸入類別是操作者聲明；工具會核對觀察到的連線類型及部位，列出不符之處，但不會認證實體來源。

3. 按實驗表做指定動作。工具只發送 `RequestSnapshot`，不改設定、不開始或停止校正、不啟動遊戲。要量動作準確度、遊戲事件或端到端延遲，需另依計畫錄影與匯出遊戲紀錄。
4. 完成後查看印出的 `experiments/<UTC時間>/`。資料夾預設不進 Git，避免將裝置資訊、個人環境與研究紀錄混入程式提交。使用 `--output <新資料夾>` 可指定儲存處；既有路徑會被拒絕，避免覆蓋原始證據。

| 檔案 | 內容 |
|---|---|
| `metadata.json` | 聲明的來源、ID 順序、備註、設定、Python/作業系統/套件、Git 狀態與差異、包含未追蹤檔案的實作 SHA-256 |
| `samples.jsonl` | 每次觀察的相對時間、最新快照接收時間、追蹤器狀態、接收累計與連線錯誤；每行獨立 JSON |
| `summary.json` | 各裝置接收率 p5/中位數、新鮮時間占比保守估計、計數重設、觀察到的連線與部位、來源或指派警告 |

`capture_completed` 代表記錄程序走完並取得快照，不代表測試通過；無快照、連線初始失敗或中途取消會標記未完成並回傳非零退出碼。中途斷線若仍能完成觀察，會保留其錯誤與過期資料，供判讀穩定性失敗；不會自動重啟後端。`automatic_hardware_acceptance` 永遠是 false，硬體驗收須連同實驗表和其他證據人工確認。

## 計算與限制

- 接收率：對每顆裝置以至少 1 秒的相鄰觀察視窗計算 `received_packets` 增量除以實際時間。視窗不跨越裝置消失或計數重設；未滿 1 秒的尾段不計。這是近似 1 秒視窗，不能當原始封包到達時序。沒有可用視窗時是 null，不能解讀成零丟包或通過。
- 百分位：排序後在 `(n-1)*p` 的位置線性內插；報告同時保留有效視窗數。
- 資料新鮮度：快照中的 `last_update_ms` 再加上接收快照後的時間，以 0.5 秒為界。在兩筆觀察之間假設沒有新資料，只計能確定未過期的時間；因此是保守估計，包含起初未收到快照的時間。WebSocket 觀測延遲與取樣間距仍會影響估計。
- 快照累計只代表後端接受的封包；不是 BLE 無線層的傳送次數，不能由此宣稱 BLE 物理層零丟包。
- `rotation` 是後端快照中的追蹤器方向，並非完整人體重建的準確度。校正、漂移與延遲需另訂分析及參考真值。
- 來源可能被混用；BLE 以外的 UDP 尤其不能僅靠 ID 判斷實體。查看 `source_or_assignment_warnings`，並與實物、影片及啟動程序對照。

輸出含個人機器資訊、設定與未提交程式差異，對外分享前先檢查。完整內部證據保留原檔；發表用表格另製匿名副本。

## 軟體自我檢查

```powershell
..\.venv\Scripts\python.exe tests\test_record_experiment.py
```

測試覆蓋穩定接收、計數重設、缺席裝置、快照凍結、WebSocket 斷線與唯讀指令。模擬測試本身不構成實體驗收。
