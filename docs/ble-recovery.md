# BLE 自動恢復

修正來源：服務搜尋、訂閱或建立通知串流失敗時，舊流程可能保留 seen_ids，使之後的裝置更新被永久跳過。Windows 已連線但沒有本程式訂閱任務的殘留連線也會被跳過。

目前每次嘗試由 ConnectionClaim 持有裝置標記；失敗提前返回、正常斷線及通知任務取消都會釋放。無任務持有的 OS 連線會先斷開後重建。連線、服務搜尋、訂閱、通知串流建立、同步寫回及斷線操作設有逾時。每五秒重新檢查已發現的裝置，不依賴 Windows 再送一次發現事件。裝置真的完成訂閱後才回報 ble_connected。

這些重試處理的是軟體恢復，不會喚醒未供電的 IMU，也不會自動猜測裝置綁在哪個部位。省電期間沒有資料是正常情況。

驗證命令：`cargo test --release reconnect_tests`；測試失敗嘗試釋放本裝置且不影響其他裝置，以及取消通知任務後允許重連。硬體斷電／喚醒的端到端驗收須另外觀察真實通知，不可由單元測試推論完成。
