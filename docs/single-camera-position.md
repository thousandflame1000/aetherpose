# 單相機位置錨定設計 v1

狀態：已實作相機擷取、鏡頭校正、標記水平定位、共用角色位移、遮擋防護與主介面控制；未提供真人實測定位精度。操作及實作邊界見 [camera-anchor-runtime.md](camera-anchor-runtime.md)。本文件保留完整設計，短時 IMU 預測融合與腰牌到骨盆剛性偏移尚未完成。

## 決策與邊界

使用一台固定 RGB 相機、腰部剛性標記板及固定地面參考板。IMU 繼續提供肢體旋轉；相機以有實際尺寸的標記提供位置觀測。第一版校正水平 X/Z，垂直位置維持現有模型與地面約束，蹲起保留局部姿態；不宣稱垂直絕對定位或跳躍高度已解決。

兩張標記板不等於兩台相機。腰部板隨人移動，地面板定義世界原點、地面與方向，也能在可見時檢查相機是否被移動。只有腰部板可見時可沿用已記住的相機外參，但不能宣稱已檢查相機仍固定。參考板位置被改動也必須重新對齊。

第一階段面向相機、在可見活動區內側移與前後移動。單面腰牌背對相機時不可見；第一版接受遮擋降級，不承諾 360 度追蹤。後續可做多面剛性標記架並校正各面到同一腰部座標，仍只用一台相機。

相機本身可獨立驗證位置，不要求湊滿六顆 IMU。有六顆已校正實機時才採用 TransPose 根位移作短時預測；只有一顆手臂時，位置來自相機，手臂姿態來源另行標示，其他肢體不能冒充實測。

## 實體配置與初始設定

1. 相機固定於螢幕或腳架，俯仰角讓腰牌及地面參考板進入同一畫面。以實際預覽決定距離，避免先假定任何鏡頭都有固定可用公尺範圍。
2. 腰牌固定在腰帶硬底座，靠近骨盆前方；不用軟紙直接黏會晃的衣服。初版測試可用黑色外框邊長 120 mm 的 ArUco 圖樣，加留白；這是試作選擇，不是保證可辨識距離。列印後用尺量外框，避免「符合頁面」縮放造成比例錯誤。
3. 地面參考板具有已知標記位置與尺寸，固定不動並標出世界前方。與腰牌使用不同 ID。角點不完整、太小或曝光不佳時拒絕定位。
4. 校正鏡頭內參及畸變，保存相機識別、實際解析度、K/D、標記實測尺寸與校正版本。改焦距、裁切、數位變焦或無法確認成像設定時重新校正，不直接套舊參數。
5. 看見地面板後建立外參；使用者在起點站直、面向預定前方，量測或估計並記錄腰牌到骨盆的剛性偏移。這個偏移有誤差，不能把「腰牌中心」直接叫作精確骨盆位置。
6. IMU 的安裝校正獨立於相機校正。具備可靠全身姿態時，用共同站姿／面向對齊 IMU 模型與地面世界的水平旋轉。未建立對齊時，不融合模型根位移。

## 座標定義與資料流

記號 T_A_B 表示把 B 座標轉到 A。C＝相機、F＝地面板、M＝腰牌、P＝骨盆；W 為由地面板轉成 Y 向上的遊戲追蹤世界。

```text
相機影像 → 角點偵測 → 腰牌 T_C_M、地面板 T_C_F
                                 ↓ 已知尺寸、內參與畸變
                     T_W_P = T_W_C × T_C_M × T_M_P
                                 ↓ 水平位置、品質、時間戳
六顆實機 → TransPose → 對齊後的根位移 → 位置融合器
                                 ↓
                    同一份追蹤根位置／來源狀態
                                 ↓
        joints 與 skinning translation 同步套用 → 場景碰撞
                                 ↓
                 攻擊、接球、搬運、距離與相機跟隨
```

OpenCV 相機軸通常為 X 向右、Y 向下、Z 向前；不能把 tvec 原封不動當成遊戲 X/Y/Z。採用顯式 4×4 變換並測試左右、前後及鏡像顯示。畫面預覽可鏡像，定位計算不使用鏡像影像座標。

單一平面標記可能有多個姿態候選。PnP 應保留候選並以正深度、重投影殘差、可接受的法線與時間連續性選取；仍有歧義時拒收。優先使用剛性多標記板改善觀測，而非把時間平滑當成真實消歧證據。

## 融合方法：先做能解釋與驗證的版本

以地面座標中的模型水平位置 m(t) 作短期預測，保存偏移 b；追蹤位置為 p(t)=m(t)+b。相機觀測到 c(t_c) 時，以同一時間的歷史模型 m(t_c) 計算 b_target=c(t_c)-m(t_c)。按觀測品質平滑更新 b，並設修正速率上限。相機沒看到標記時不繼續製造新的位置觀測。

不能直接拿舊相機位置和「現在」模型位置相減，否則正常移動會被當成漂移。保留帶時間的模型歷史環形緩衝，對 t_c 插值。若缺少對應歷史、標記過期、影像時間不確定過大或序號倒退，拒收。所有本機服務使用同一 monotonic 時鐘；記錄影像擷取、偵測完成、模型輸出與瀏覽器收到的時間。一般 webcam 的 host 擷取時間不等於曝光時間，必須將緩衝延遲列為不確定性，不能虛稱硬體同步。

只有相機位置時，用相機位置的平滑軌跡作 p(t)，不引用混合／示範 TransPose 根位移填洞。不把手臂 stationary 當成整個人停止的證據。

品質條件包含角點大小、完整性、重投影誤差、距離／視角、姿態候選歧義、時間延遲、固定地面板一致性及跨幀跳變。先保存各分量，再決定採信；不以未校正的 confidence 百分比冒充真實準確率。

## 遮擋與恢復狀態

| 狀態 | 根位移處理 | 遊戲行為 |
|---|---|---|
| 未設定 | 不接受相機位移 | 顯示架設／校正步驟 |
| 追蹤中 | 接受通過品質檢查的視覺修正 | 允許依賴位置的互動 |
| 短暫遮擋 | 有可信六顆模型才短時預測；純相機模式保留末位置 | 顯示降級，限制新位置事件 |
| 位置失效 | 固定最後可信場景位置，持續更新可用肢體姿態 | 暫停依賴位置的計分，不判碰撞失誤 |
| 重新捕捉 | 累積一致觀測後受限速率校正 | 恢復期間不觸發穿越／攻擊／接球事件 |
| 需重設 | 相機／地面板位置矛盾、尺寸／內參版本改變 | 暫停位置玩法，重新建立世界 |

可調原型參數：短暫遮擋 0.3 秒、0.8 秒後判失效、重新捕捉至少 5 個一致影格。這些數字只是試作設定，須依實際延遲、噪聲與玩家移動速度調整，不是已驗證門檻。恢復位置差過大時要求重設，不強行慢慢拖動角色穿越房間。

## 現有專案接入點

| 檔案／擬新增元件 | 改動 |
|---|---|
| `frontend/camera_anchor.py`（擬新增） | 相機擷取、標記偵測、PnP、品質檢查。獨立 worker，單一最新影像佇列，避免積壓拖慢姿態推論。初版將選定並鎖定一種具 ArUco 的 OpenCV 套件，不同 OpenCV wheel 不混裝。 |
| `frontend/root_position.py`（擬新增） | 時間緩衝、座標變換、融合偏移、遮擋／恢復狀態；可離線重播測試。 |
| `frontend/transpose_runner.py` | 保留原始模型 translation；輸出時將修正差 Δ 同時加到 joints 及 skinning translation。相機修正不直接寫進 RNN 隱狀態。 |
| `frontend/mesh_bridge.py` | 傳送根位置狀態與來源，處理啟停／校正；相機錨定的時序不能綁在模型完成影格才更新。 |
| `webui/avatar.js` | 移除每包追蹤都抵消骨盆位移的行為，改固定起始錨點；UI 模式切換保留角色位置。 |
| `webui/physics.js`、`combat.js`、`games.js` | 保留連續掃掠。位置重捕捉／重設不能算作玩家攻擊速度或穿越得分。 |
| 網頁定位面板、紀錄 | 顯示相機位置／短時預測／位置失效及觀測年齡，與 pose source 分開；紀錄校正版本、遮擋與拒收事件。 |

新增傳輸資料以實作時版本化 schema 定義，至少包含 observation sequence、capture monotonic time、world epoch、position source、raw model root、fused root、anchor age、state、reject reason、calibration revision。位置狀態改變時即使沒有新模型姿態也須送出。回放資料標示 synthetic，不寫入實機成績。

追蹤根位置與遊戲碰撞後位置分開：碰撞可阻止虛擬角色，不能回寫成相機量測。真實玩家走過虛擬牆後，遊戲提示玩家退回活動區，避免把累積的碰撞偏差當成感測漂移。場景跟隨鏡頭只改相機，不修改身體位置。

## 玩家流程

「設定定位」→ 選相機並開啟預覽 → 輸入／選用實測標記尺寸與相機校正 → 框住地面參考板 → 腰牌可見、起點對齊 → 看到位置狀態才開始。

相機只在本機擷取；預設不保存影片，記錄幾何量與事件。開鏡頭需由使用者操作；本次設計頁不會要求攝影機權限，也不會啟動硬體。

## 實作與驗收順序

1. **相機獨立驗證**：真實列印板、內參、水平位移顯示及世界軸向。不依賴模型先跑通。量測不同距離、角度、照明下的誤差、延遲和失敗率。
2. **共用根位置**：將獨立相機軌跡接進角色、骨架、碰撞及命中，測試同一座標的一致性；修正 Combat 位移抵消。
3. **融合與遮擋**：以錄製幾何資料驗證延遲對齊、離群值、短遮擋、長遮擋、恢復、相機移動及來源切換。
4. **真人遊戲驗收**：先測側移躲障礙及接近／遠離，再測旋轉、蹲起。身體姿態與位置精度分開報告。

量測項目：靜站 60 秒的水平偏移；沿地面尺規左右／前後移動並返回起點的偏差；真實軌跡與估計軌跡差；遮擋後恢復時間與最大修正跳變；延遲分布；錯誤鏡像、錯誤尺寸及相機被搬動時是否拒收。比較「模型原始位置」「相機觀測」「融合輸出」，不得只展示比較漂亮的一條線。

驗收門檻等實體相機與鏡頭條件確定並完成基線後訂定；目前不承諾公分級或永久不漂移。

## 依據與原創邊界

- [OpenCV ArUco 官方教學](https://docs.opencv.org/4.x/d5/dae/tutorial_aruco_detection.html)：已知標記尺寸與內參取得姿態及公制平移；多標記板可支援部分遮擋。
- [OpenCV PnP 說明](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)：相機／物體座標變換與姿態求解。
