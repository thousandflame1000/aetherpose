# 深蹲試次標註與分析

此流程對應 G6，分析遊戲在預先劃定試次中是否計分，不能量測三維關節精度，也不自動驗收硬體。程式測試用的合成資料不算受測者成果。

## 先固定測法

先完成六顆裝置指派、身體校正與遊戲站姿校準，再開始正式試次。頁面已禁止未校正的即時／混合輸入開局；開始身體校正或校正失效會中止回合，該回合不更新完成成績。既有歷史成績不因這項修正而重新獲得驗證。

每位參與者預先排定 20 次完整深蹲與 20 次負例（例如 10 次僅低頭、10 次彎腰），至少三人；人數不足時明寫單人／小樣本限制。每個試次只安排一個指令動作，中間回到站姿，試次起訖、動作定義與順序先記在實驗表。不得事後把未得分的動作刪除或變更為負例。動作幅度與安全範圍由參與者自行決定，不作醫療或訓練效果結論。

用同一段影片拍到動作與遊戲計分畫面，保存影片幀率與試次區間。人工先標記是否為預定完整深蹲，再標記該區間是否有遊戲計分；建議由另一位組員複核。負例期間有任何計分就記為 detected=1。完整深蹲有一次以上計分記為 detected=1，同時另記重複計分次數；二元工具本身無法衡量重複計分。額外動作與背景計分不能靠事後新增負例改變分母，另列為異常事件。

## CSV 與執行

以下只有欄名，另建自己的 `trials.csv` 填入實際觀察，不使用單元測試資料替代實測：

```csv
trial_id,expected,detected,action_at_s,detected_at_s
```

- trial_id：每個檔案內唯一，例如匿名參與者 P01 的 P01-S01；另外保留影片與試次區間對照表。
- expected：完整深蹲為 1，事先排定的負例為 0。
- detected：試次區間有遊戲計分為 1，否則為 0；不能用回合總分自行分攤。
- action_at_s、detected_at_s：可留空。若填寫，兩者必須使用同一影片原點或已驗證的同步時基。動作時間的定義先固定，例如達到既定下蹲條件的影格；計分時間為首次可見分數變化的影格。若 expected=0，action_at_s 必須空白；detected=0 時 detected_at_s 必須空白。

```powershell
..\.venv\Scripts\python.exe tools\analyze_trials.py --input experiments\YOUR_RUN\trials.csv --output experiments\YOUR_RUN\trial-summary.json --run-id YOUR_RUN --source physical-ble --timebase same-video
```

來源由操作者宣告：physical-ble、physical-udp、simulated-udp 或 mixed。來源字串不是實物驗證，必須與 ID、錄製、實驗表及版本對照。輸出不覆寫既有檔案；更正標註時保留原稿並使用新檔名。摘要保存輸入與分析程式 SHA-256，以便重算。

## 解讀結果

TP／FN 以正例試次為分母，FP／TN 以負例試次為分母。輸出 precision、recall、F1 與負例誤判率；分母為零寫 null。G6 目前預定召回率至少 90%、負例誤判率至多 10%，應逐人列出原始分子／分母，再另列彙總，不能只挑最好的一人。二元試次統計不等於連續事件偵測準確率，重複計分要另列表。

成對時間差為「觀察到的計分時間 − 定義的動作時間」。工具保留負值、缺少成對時間的數量及逐筆差值，中位數／p95 採 `(n-1)*p` 線性內插。負值要查標註或判定條件，不能直接裁成零。此差值包含動作規則、影格解析度與畫面觀察，不能稱為純推論延遲。G7 的真人起動至畫面起動，使用另一組獨立標註，不能用這份計分差值替代。

測試命令：`..\.venv\Scripts\python.exe tests\test_analyze_trials.py`。測試覆蓋已知混淆矩陣、空分母、負時間差、重複試次、無效數值、未宣告同步時基及防覆寫；測試通過不代表任何參與者的深蹲判定已驗收。
