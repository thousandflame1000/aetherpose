## Fixes worth knowing

Behaviour that changed for a reason the code alone does not show.

### Backend

- OSC: VRChat ignores named addresses, so trackers go out as `1`–`8` plus `head`, with rotations mirrored into Unity's left-handed frame and sent as Euler angles applied Z, X, Y ([VRChat OSC Trackers](https://docs.vrchat.com/docs/osc-trackers)). An unusable target leaves the working target and config in place and is reported (`osc_active`, `osc_error`). The backend only takes IP literals, so `localhost` is refused, and port 0 or `0.0.0.0` (which receive nothing; send errors are not reported per frame) are refused too instead of looking active.
- UDP tracker input listens on its own port 9003 (`udp_input_port`). Sharing 9000 with OSC output made the backend receive its own packets, and with VRChat holding 9000 the whole backend stopped.
- Headset input older than 500 ms is ignored (`headset_age_ms`); a single Quest packet used to pin the head and hands forever.
- The headset bridge read datagrams into a 256-byte buffer, but head and both hands with full-precision floats need more (396 bytes in the live test), so such poses were lost; the buffer is 2 KB. A pose with non-finite numbers or a zero quaternion (normalised to NaN) is now dropped instead of reaching the IK.
- One tracker per body part: assigning an occupied part swaps the two trackers, from the menu and from shake-to-assign. A tracker connecting later does not reshuffle saved assignments.
- The bone menu offered 「未指派」, but choosing it sent nothing and the next snapshot put the old bone back. It now unassigns (`UnassignTracker`); the tracker stays without a bone when other trackers connect and after a restart (`unassigned_trackers` in config.json) until it is assigned again or 「自動指派」 is pressed. Checked live with a UDP tracker across a backend restart. Assignments and shake-to-assign to a bone the skeleton does not have are ignored instead of saved.
- Leg calibration reports its outcome (`done`, `no_samples`, `small_swing`, `unsolvable`, `out_of_range`).
- Starting a recording under a name already used truncated the earlier recording without a word. Recordings are now created with `create_new`: an existing `walk.csv` makes the new one `walk_2.csv` (the page shows the actual name). Windows device names (`nul.csv`, `CON`, `COM1`, ...) are refused, since writing to them discards the data.
- Recording creates its file before reporting the start, so a name Windows cannot create is reported (`recorder_error`) instead of showing "recording" while nothing is written. Files go to `recordings/`.
- A recording batch size from another client sized a buffer up front: 10^12 aborted the whole backend (reproduced live). Batch size and write interval are now kept to the page's 1-10000 and 10-60000 ms.
- A ZUPT window of 0 made the stationary window grow without bound; it is now kept to 1-200 samples like the page, in the detector itself, so a hand-edited config.json cannot size a huge buffer at start-up either, and thresholds that are not positive numbers are refused.
- IK smoothing, proportions, drift, filter and floor settings were stored as sent. The page's sliders keep them in range, but any local client could send 7.5 or an f32 overflow (infinity), which config.json cannot even hold. The backend now clamps them to the sliders' ranges and refuses non-finite values; the reply snapshot puts the slider back.
- An unreadable config.json is copied to `config.json.bad` and reported (`config_warning`) before defaults are saved over it.
- A config.json without the filter settings (saved before they existed) loaded `smoothing_min_cutoff` and `smoothing_beta` as 0 instead of 3: the field-level `serde(default)` takes the type's zero, and a cutoff of 0 freezes the One Euro filter. Missing settings now take `AppConfig::default()`, a config missing any other setting (which used to be rejected whole) loads with defaults for the gaps, and out-of-range or non-finite values are brought into range at load with a warning in the log.
- Any web page could open a WebSocket to 9009 or 9010 (browsers do not apply the same-origin rule to WebSockets) and, for example, point OSC output at another machine. Both services now accept only pages from this machine (`http://127.0.0.1`, `localhost`, `[::1]`, any port) and programs that send no Origin; anything else gets 403 and is logged.
- Tracker input: a packet carrying NaN or infinite readings, or a quaternion far from unit length, went straight into the filters and the IK, where it never washes out (and out over OSC). All three paths (BLE, UDP, serial) now drop such packets; UDP 9003 accepts any sender on the network, so this also covers stray traffic.
- Serial input parsed each read as whole lines, but reads return arbitrary chunks: a JSON line split across two reads was lost on both sides and logged as an error, and a split multi-byte character dropped the whole chunk. Lines are now reassembled across reads. The port's 500 ms read timeout was also treated as a failure, so half a second without data reconnected the port; it is now ignored.
- A fuzz run of 400 malformed and extreme commands (wrong types, overflowing numbers, 5000-character garbage) left the backend running with every setting in range. It showed that an unrecognised message was logged whole; the log line now keeps the first 200 characters.
- 3000 hostile datagrams to UDP 9003 and 9002 (random bytes, frames with bad CRCs, packets full of NaN, infinity or zero quaternions, broken headset JSON) created no tracker and no headset pose, and the backend kept running.
- The page server answered path traversal attempts (`/../config.json`, encoded and backslash forms) with 404 or a redirect inside `webui/`. A path with a NUL byte crashed the request (dropped connection, traceback in the log); it now gets 400.
- Commands a client sent just before disconnecting could be lost: when sending to a closed client failed first, the backend aborted the receive side before it had forwarded them. It now lets the receive side finish (up to 2 s). Found by the simulated-tracker check, which failed about half the time before and passed six runs in a row after.
- `ForgetTracker` drops a tracker completely (list, assignment, config.json); `tools/simulate_trackers.py` sends it for its IDs when it stops. About one stop in twelve still left five of the six trackers listed for a moment: the backend can take the six commands over two of its 10 ms ticks, and the snapshot between them still lists the rest. The simulator now waits for a snapshot without its trackers (15 stops in a row clean after).
- The page received about 17 poses a second while the model made about 50: the pose service sent on a fixed 30 Hz sleep, which on Windows waits in 15.6 ms steps (asyncio's clock there is `GetTickCount64`), and it compressed every pose and mesh once per page (websockets' default permessage-deflate), which took about a quarter of a core from the thread the model shares Python's GIL with. It now sends each pose as soon as the model makes it, uncompressed: the page gets all of them (about 45 a second), that thread uses 8 % of a core instead of 24–30 %, and the model's own rate is unchanged. The motion-to-pose median fell from about 170 to 133 ms.
- When inference was slower than the 60 frames a second the pose service gathers, the model was handed only the newest frame and the rest were dropped. It was trained on 60 a second, so it then saw motion sped up: against the same model fed every frame, its joints were 4.7–7.7° off on average (35–54° at worst) and the root drifted 47–59 cm in 1.5 s, and its 5-frame lookahead stretched with each slower pass. Now every waiting frame (up to 8) goes into one pass over the window extended by those frames, for little more than the cost of one (`forward_online_frames`; one frame per pass is TransPose's `forward_online` exactly): 0.2–0.6° off on average, root within 6–12 cm. On the same throttled CPU (A/B, simulated trackers switching between standing and squatting) the pose was halfway after a median of 191–195 ms instead of 326–335 (worst 225 against 414). The frame pump also keeps 60 a second on a fixed schedule; sleeping 1/60 s after its work gave about 58.
- The backend skeleton (the one sent to VRChat over OSC) placed each joint by the bone's own rotation instead of its parent's. A turn of the hips therefore swung the whole body about the floor: with simulated trackers squatting, the IK head ended at -1.1 m and the hips at -0.9 m and stayed below the floor after standing up. Every tracker also turned the segment above its own (the shin tracker turned the thigh). Forward kinematics now use the parent's rotation, as the knee limits, the CCD step and the leg calibration already assumed; the CCD step also turns its world-space correction into the bone's parent frame. The same squats keep the hips at 1.00 m.
- The root of that skeleton never moved, so a headset lower than its head, or anywhere but above the origin, was out of reach: a 1.65 m headset left the IK head at 1.75 m, and walking left every body tracker behind. The headset now anchors the body: once every rotation is set, the whole skeleton moves so the head is exactly where the headset is (1.65 m standing, 1.14 m at the bottom of a simulated squat, the hips going from 0.90 to 0.45 m); without a headset it stands where it did.
- Drift compensation did almost nothing: each frame it blended the hips' heading 1 % (at full strength) toward the headset's and kept nothing, so a 30° drift stayed at 29.1° however long it ran. It now keeps the correction it has made and closes a little more each frame, about 10 s to converge at full strength (a brief head turn barely moves the hips); turning it off, resetting yaw or clearing calibration drops the correction.
- A leg calibration could only be redone, not undone: 「重設比例」 now puts the ratio back to 0.900 (`SetLegRatio`, kept within 0.2–3.0 like the saved setting).
- The body mesh is now skinned in the page. The pose service used to compute it every fourth pose and send each page an 82 KB binary mesh (about 12 a second, 1 MB/s per page), which the page eased toward over about 56 ms, so the body trailed the joints the games use. Now it sends the SMPL template, rest joints and four bone weights per vertex once per connection (812 KB of JSON; every SMPL vertex has exactly four weights, so nothing is lost), then each pose's 24 joint rotations (about 3.3 KB per pose message). The page skins every pose (1.5 ms on average in headless Edge with software rendering) and eases over about 33 ms. The service no longer runs a mesh thread, and its messages are all JSON.
- The tracker simulator's accelerometer read (0, 0, 9.81) in the tracker's own axes even while tilted, which the pose service takes as up to about 1 g of linear acceleration on a still tracker (and its magnetometer did not turn either). Both now read the world's gravity and field in the tilted tracker's axes.
- UDP input read a packet before checking the per-tick budget (50), so once a tick reached the budget the packet just read was dropped and counted as lost. The budget is now checked before reading: a burst of 300 packets from one tracker now arrives with 0 lost.
- A backend that cannot bind 9009 exits with code 1 instead of 0 (it logged the error and ended as if it had succeeded), and a server error is logged instead of panicking. `mesh_bridge.py` prints one line instead of a traceback when 9010 is taken.
- On Windows the page server and `tools/imu_axes.py` could start a second copy on a port already in use: Python's HTTPServer sets SO_REUSEADDR, which Windows treats as permission to share a listening port, so the two copies split the connections. Both now bind the port exclusively on Windows and say the port is taken (test `test_a_second_server_cannot_take_the_port`; restarting still rebinds at once).
- Bluetooth status reaches the page (`ble_status`); before, Bluetooth problems were only in `logs/status_ble.log`. Advertisements from unrelated devices and all-zero backpressure stats (about 95 % of the log) are no longer logged at info level.

### Pose service

- Live trackers are calibrated before TransPose (`frontend/body_calibration.py`): a T-pose gives the mountings, then a forward bow gives the facing direction from the torso tracker's tilt, so no sensor axes are needed. Raw firmware orientations (Z up, mounting included) used to go straight into the model.
- With no page connected the pose service still ran inference at full speed on the demo data, about two CPU cores for nothing. It now infers only while a connected page can be seen (the page reports when its tab goes to the background), or while a body calibration needs the frames; a pause longer than a second restarts the pose-rate average, so a page that connects does not briefly see the slow-rate warning.
- TransPose, SMPL, weights and DIP-IMU locations come from `external_paths.json`; SMPL kinematics are in the project (`frontend/smpl_fk.py`).

### Web UI

- Bow Rhythm takes "forward" from the feet and Dodge Flow measures along the shoulder line. Both were mirrored for real SMPL output (left at +x), which the synthetic test skeleton (left at −x) did not show; the tests now run both handednesses. The other games were checked for the same mistake: they pick sides by SMPL joint index (left knee 4, left foot 10, left hand 22, ...) or measure along the shoulder line, so they are unaffected. Combat's side-lean dodge measured the head's offset on world x, so bending forward counted as a dodge whenever the player was not facing exactly +z; it now measures along the shoulders too (the test fails on the old code).
- A pose source change (for example a tracker dropping out for just over 0.5 s) pauses the round for up to 1.5 s before ending it, so records never mix sources.
- Starting body calibration, or changing a solid scene object, ends a running round as unfinished.
- A lost WebGL context (GPU reset) used to leave a frozen picture with no explanation, and a round kept scoring unseen. The round now ends as unfinished and the panel says the 3D view is recovering, or asks for a reload after 8 s; tested with `WEBGL_lose_context`.
- 「清除紀錄」 deleted up to 50 rounds at one click, with no way back (they live only in the browser). It now asks first, and best scores, which the game cards and results now show for pose games and Combat alike, have their own confirmed 「清除最佳成績」.
- Round end reasons are stored as English codes (`Time's up` marks a completed round) and translated only for display, so existing history and best scores stay valid.
- The local tool API in `webui/server.py` (magnetometer calibration and flashing) needs a localhost Host, a matching Origin and the `X-Aetherpose` header.
- Cancelling a tool run stopped only the Python tool: the arduino-cli compile or upload it had started kept running, holding the COM port, after the page said the run was cancelled. The whole process tree is stopped now (`taskkill /T` on Windows, a process group elsewhere); the test fails on the old code. `stop.ps1` stops each service with its process tree as well, so stopping the services mid-run leaves no tool behind.

- `EXTERNAL_DEPENDENCIES.md` named Madgwick AHRS as the tracker filter; the firmware has used x-io Fusion AHRS (Madgwick's successor, MIT, bundled with its licence) since the Fusion switch. The disclosure, the suggested report wording and the references now say so, and the Quaternius robot (CC0) is listed.
- The docs said `run.ps1 -Restart` after an update, but nothing rebuilt the backend, so a Rust change kept running the old `aetherpose.exe`. `run.ps1` now runs `cargo build --release` before starting a backend older than `src/**/*.rs`, `Cargo.toml` or `Cargo.lock`, and warns when the running one is older (checked both ways by touching a source file).
- `.gitignore`: dropped patterns for files nothing produces any more; every service log is under `logs/`.
- `cargo clippy --all-targets` is clean and part of the check run: derived `Default`s, the channel snapshot is boxed, and the trajectory estimator takes one `ImuSample` instead of four loose arguments.
- `webui/index.html` held 344 lines of CSS and a 2,200-line script. They are now `app.css` and eight page scripts with the same load order (map in `webui/README.md`).
- Interface text: slogans in the training hall, instructions repeated across cards, status lines that restated their buttons, and section summaries that listed their own contents are gone. Solver numbers and the Combat pose/mesh lights show only with the debug views; a slow pose rate is reported in words. The hall scoreboard's states (準備就緒, 剩 n 秒, 暫停, 完成, 中斷) are in Chinese like the rest of the interface.
