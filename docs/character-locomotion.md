# 人物位移與漂移抑制要求

使用者要求：後續遊戲必須把人物位移納入邏輯，並處理絕對位置漂移。本文件是實作規格；以下尚未實作的項目不能當成已完成功能。

## 已查到的現況

- `frontend/transpose_runner.py` 的 `forward_online_frames` 已融合模型根速度與預測足部接觸，並限制足部穿地；推論迴圈以初始 translation 為原點，同時輸出帶位移的 joints 與網格 translation。
- `webui/avatar.js` 的 Combat 路徑在每個 onJoints 更新 anchor，applyTransform 再減去骨盆水平位置，會抵消人物水平位移。解除抵消時，須同時驗證遊戲距離、相機與碰撞，而非只讓網格走動。
- `webui/physics.js` 已對角色整體做碰撞修正與連續掃掠；位移應沿用這條路徑。
- 缺少的感測器槽位以示範資料補入。單顆手臂與混合資料不能被當成人的步行或絕對位置證據。

## 實作約束

1. 將輸入估計位置、場景出生位置、碰撞修正與重新置中分開保存。全身關節、網格、攻擊點和判定目標必須使用同一個世界轉換；不能網格走了而碰撞留在原地。
2. 使用 TransPose 根位移作正式身體移動預測時，以六個已校正、持續更新的實體槽位為前提。混合／示範模型位移只能用於明確標示的回放。外部相機錨定可獨立提供位置，無需湊滿六顆 IMU；但肢體姿態來源仍須分開標示，不能因此聲稱單顆 IMU 已完成全身追蹤。單相機方案見 [single-camera-position.md](single-camera-position.md)。
3. 改用固定的活動起始原點，保留後續根位移；切換模式、斷線恢復與重校正要重建輸入基準，保留場景中的角色位置，避免瞬移或恢復後補上斷訊期間的位移。
4. 對非有限值、過期資料及不合理位置跳變拒收或暫停移動，不得以夾住座標掩蓋追蹤已失效。速度與跳變門檻須經穿戴量測，不能宣稱是定位精度。
5. 候選漂移抑制：可靠的足部靜止／接觸期間約束速度與落腳點；移動時放開限制。接觸是模型估計，還需實測；雙腳離地時不得硬鎖。手臂不動不代表整個人不動，不能用單顆手臂的 stationary 直接把人鎖在地上。
6. 提供明確的重新置中／實體基準點對齊。磁力計只能輔助朝向，不是位置錨點。若要求長時間對齊房間內的絕對座標，需接入外部定位來源，例如視覺標記、視覺追蹤或有實際定位能力的裝置；須評估量測頻率、誤差和時間同步。

## 驗收

- 同一組前進／側移輸入，在訓練與 Combat 中，網格、骨架、命中位置及碰撞一起移動。
- 連續跨越障礙不穿牆；相機跟隨不修改角色位置。
- 靜站測試量測每分鐘位置變化；直線往返量測回到起點的偏差。保留原始 IMU、模型位置、修正位置、來源及時間戳，不編造通過門檻或精度。
- 單腳支撐、抬腳、蹲起、雙腳離地、慢速挪步需檢查是否誤鎖；斷訊再連線及重新校正不瞬移。
- 六顆實機與單顆／混合來源分開驗證，不能用合成資料通過代替真人定位驗收。

## 研究依據

- [TransPose 作者程式與論文入口](https://github.com/Xinyu-Yi/TransPose)：根位移結合足部接觸推估與速度回歸；這不是外部絕對位置量測。
- [x-io IMU 定位說明](https://x-io.co.uk/contact/)：IMU 不直接量測位置；特定應用可藉專用演算法間接估計，一般位置追蹤需評估 GNSS 或相機等來源。

目前已完成相機模式的共用水平位移及失效防護，見 [camera-anchor-runtime.md](camera-anchor-runtime.md)。尚未完成 IMU 短時位置融合與真人量測，不能承諾只靠現有 IMU 消除全部絕對位置漂移。
