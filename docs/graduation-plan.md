## 1. 成果定位與範圍

題目暫定「基於六顆慣性感測器之即時全身動作捕捉與互動展示系統」。本專題的貢獻是韌體、BLE 接收、資料整理與身體校正、TransPose 串接、瀏覽器人體呈現及互動判定的端到端工程實作。TransPose 模型、預訓練權重、SMPL 與外部素材均需獨立標示來源，不宣稱自行提出人體重建模型。

核心驗收只保留一條完整流程：六顆實體 IMU → 指派 → 身體校正 → 即時人體 → Squat Rhythm。其餘小遊戲、Combat、場景編輯與 Quest/OSC 是延伸成果；核心穩定後才投入修飾。暫不新增遊戲、訓練新模型、多人追蹤或醫療用途。

「成熟」的完成定義：能由另一人依說明安裝啟動，能用實體輸入重複完成展示，有原始紀錄支持所有量化結論，報告和程式一致，提交包與展示中可辨識外部依賴及資料來源。

## 4. 預先訂定的驗收門檻

以下數字是工程目標，尚未量測，不得先寫成成果。若目標未達，先分析瓶頸，再保留調整原因；不得事後只挑成功片段。

| ID | 測試方法 | 目標／判定 |
|---|---|---|
| G1 軟體基準 | 執行既有完整檢查，再執行 `-Live`；保存命令、環境與退出碼 | 必要檢查全通過；跳過的項目逐一揭露 |
| G2 安裝重現 | 另一台 Windows 或乾淨帳號，合法自備外部模型，依文件操作 | 不修改原始碼或硬編碼個人路徑即可啟動並看到人體 |
| G3 六顆穩定 | 實體 BLE，穿戴後連續 10 分鐘，逐顆記錄接收時間與序號 | 六顆各 1 秒視窗接收率 p5 ≥20 Hz；每顆樣本新鮮度 ≤0.5 秒的時間占比 ≥99%；無程序崩潰 |
| G4 校正重複性 | 同一人重新穿戴與校正 3 次，記錄耗時、成功與原因 | 3 次均可完成；單次操作目標 ≤2 分鐘，不含初次磁力計校正 |
| G5 漂移 | 靜止 60 秒，取前後各 5 秒平均肢段方向，保留四元數與感測器位置 | 主要肢段方向差目標 ≤10°；分別報告各部位，不把漂移當絕對準確度 |
| G6 互動正確性 | 每人 20 次完整深蹲，另錄 20 次僅低頭／彎腰；影片人工標註並對齊遊戲事件 | 預期召回率 ≥90%、負例誤判率 ≤10%；至少 3 人或明確揭露單人研究限制 |
| G7 端到端延遲 | 外部影片同框拍真人與畫面，至少 20 次站立／下蹲轉換，標註起動影格 | 報告中位數、p95、影格解析度；目標 p95 ≤300 ms，不以模型推論耗時替代 |
| G8 中斷復原 | 逐一讓追蹤器掉線、停止推論、頁面背景化，再恢復 | ≤2 秒可見異常狀態；回合不繼續累計有效成績；可按文件恢復，來源不混記 |
| G9 展示彩排 | 冷啟動並依固定腳本連做 3 次，錄製未剪輯影片 | 三次成功；故障時可解釋來源與復原，不冒充真人輸入 |

若沒有光學真值設備，禁止宣稱毫米級精度或把肉眼符合當 MPJPE。可採固定視角影片做任務判定與延遲；三維關節誤差需另有可靠的座標對齊與參考系統。

## 5. 實驗紀錄規約

每次執行分配 run_id，保存：日期、操作者代號、程式版本或變更摘要、Windows/Python/Rust/套件版本、CPU/GPU、六顆 tracker ID 與位置、韌體版本、BLE/UDP、實體/模擬、mask、校正結果、測試動作、設定、原始 log、影片路徑與結果。不得包含受限模型或可識別受測者的公開影像。

軟體模擬、資料集回放、六顆實體 BLE、Quest 擴充各自統計。實體實驗前停止模擬器並核對 ID，`LIVE 6/6` 本身不作實體輸入證明。測試失敗同樣保留；報告每項樣本數、分母、環境及限制。

先做單人試測確認流程，再進行自願參與的小規模任務測試；使用匿名代號，影片存取與使用範圍先說明。無法取得硬體的項目持續標記待驗，不填造數據。
