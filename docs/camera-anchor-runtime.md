# 單相機定位：操作與目前限制

已實作在主介面「準備 → 單相機位置定位」，不是設計動畫。相機只在按下「開啟相機」後由本機 Python 擷取，不錄影、不上傳。停止相機或關閉最後一個主介面連線會釋放攝影機。

## 使用

1. 開啟主介面 http://127.0.0.1:18080/ ，進入「準備」，展開「單相機位置定位」。
2. 點「開啟可列印腰牌、地面板與校正棋盤」。A4 橫式，100%／實際大小，關閉符合頁面與頁首頁尾。量黑框外邊長；預設 120 mm，兩張標記須相同尺寸。棋盤為 10×7 格（9×6 內角點），每格 25 mm。貼在平整硬板上。
3. 相機固定好，填編號（通常 0）與標記實測公尺尺寸，按「開啟相機」。可看到本機預覽；如果占用、權限或編號不對會明確報錯。
4. 初次使用用棋盤從不同傾角、距離及畫面位置拍至少 12 筆「收集棋盤」，再按「計算鏡頭校正」。會檢查重投影殘差並儲存到 `frontend/camera_profiles/`。這是鏡頭幾何校正品質，不是位置精度驗收。更換相機、焦距或解析度後重新校正；v1 的設定檔以裝置編號及解析度辨識，不保證裝置編號永久對應同一實體相機。
5. 把 ID 0 平放並固定在地面、ID 1 固定在腰帶硬底座，讓兩者可見。ID 0 板子的頁面右方定義場景 +X，板面向外為 +Y；不要在使用途中搬動它。
6. 在起點按「記錄位置原點」，待狀態顯示水平位置有效後再開始遊戲。相機的 X/Z 位移會套用到共用角色，骨架、網格、碰撞與命中點一起移動。
7. 相機或參考板位置改變後，按「重設參考板」，固定好再記原點。不要用程式掩蓋錯誤基準。

## 行為

- v1 用相機的腰牌中心相對原點位移，水平 X/Z 有平滑及最大修正速率；尚未量測或扣除剛性腰牌到真實骨盆的偏移。因此側身／彎腰可能有標記偏移，不宣稱是精確骨盆絕對座標。
- 取消了相機定位模式下對水平位移的抵消。原有未使用相機的模式保留既有行為。
- 不接混合／示範模型的根位移作預測。相機位置可獨立於 IMU 數量運作；肢體姿態的示範／混合／即時分類仍保留。
- 垂直方向不由相機取代，維持現有姿態及地面約束。
- 標記看不到、位置過期或相機錯誤時，固定最後位置，肢體遊戲繼續使用新鮮姿態。重新可見後先累積一致觀測，再平滑恢復位置。啟停相機、重設參考板或記錄原點會清除未完成動作並重新取得基準，保留回合分數與時間。
- 地面參考板暫時看不到時，最多沿用兩秒的外參；之後不再更新腰牌位置。可見的地面板與原外參持續矛盾會要求重設。
- 錯誤、過小、平面姿態歧義大或位置跳變異常的觀測被拒收。閾值目前是原型設定，不能當成真實精度承諾。
- 位置狀態以獨立 20 Hz 通道送出，不依賴神經網路推論完成；預覽上限約 5 Hz。相機擷取在獨立執行緒，影像不寫入磁碟。

## 驗證與尚待實測

`tests/test_camera_position.py`：已知幾何 PnP 公制位置、無效／過期資料、遮擋保持與限速恢復、相機移動重設、校正解析度、相機錯誤釋放、標記與棋盤可辨識。

`tests/test_mesh_bridge_protocol.py`：現有橋接協定、來源限制及姿態時序回歸。

`tests/webui_integration.js`：相機根位置取代模型位移、Combat 尺度及 packet-time 一致性、位置未就緒仍可開始、遮擋保留位置與肢體遊戲、訊息中斷防護。`tests/webui_continuity.js` 另驗證長時間中斷與重設交錯，既有場景碰撞與遊戲檢查仍執行。

尚未完成：使用者鏡頭的內參校正與真人移動量測、真實遮擋後偏差、剛性腰牌到骨盆偏移、多面標記、六顆實機模型短時預測融合。完整後續設計見 [single-camera-position.md](single-camera-position.md)。

本機啟動檢查：實際第 0 號相機已成功開啟為 1280×720，主介面 WebSocket 收到 JPEG 預覽，停止指令後釋放相機；狀態為 needs_intrinsics，尚無鏡頭校正檔。這只證明擷取及傳輸通路正常，不代表真人位置精度驗收。
